# Decision register

One row per structural choice a reasonable person might later reverse. A row may name what it
replaced, because the rationale stays true after the replaced thing is gone. Open decisions are not
here; they are in the [backlog](../backlog.md). Rows are never edited away: a reversal is a new row
that cites the old one.

| id | date | decision | why | cost |
|---|---|---|---|---|
| D1 | 2026-10-14 | The UI shell is built on `internal/gpui`, not Dear ImGui through cimgui-go as the specification proposed | No cgo, so the application builds for `js/wasm`; headless rendering, so UI behaviour is tested and screenshotted without a display; the library is in the repository, so the canvas gets the primitives it needs | Widgets are built by hand; the whole window is rasterized on the CPU each frame; no native look |
| D2 | 2026-10-14 | `internal/gpui` lives inside the `cad-lite` module, with its own docs and `AGENTS.md` | A canvas need and the library change that serves it land in one commit, under one `go.mod` | The library cannot be imported from another module; doc snippets are checked inside the module, under `_tmp/` |
| D3 | 2026-10-14 | The renderer draws through the gpui scene (`render/gpuirender`), not through a separate ebiten adapter painting offscreen images (the specification's `render/ebitenrender`) | One drawing path for the UI and the canvas, identical headless and in a window, and no direct ebiten use outside the platform package | No base-layer cache: every frame re-rasterizes the drawing, which bounds the drawing size the spike handles smoothly |
| D4 | 2026-10-14 | The file I/O layer is the package `fileio`, not `io` | `io` would shadow the standard library package in every importer | The path differs from the specification's layout |
| D5 | 2026-10-14 | Entities and tables live in package `doc`, not in `doc/entities` and `doc/tables` subpackages | Entities need `EntityCommon` and the drawing needs entities; one package has no import cycle to break | A larger package as entity types are added |
| D6 | 2026-10-14 | The spatial index is a linear scan behind the API an R-tree serves | The spike's drawings are small; callers do not change when the R-tree lands | Query time grows linearly with the drawing |
| D7 | 2026-10-14 | The DXF writer emits R12 (`AC1009`) | No object dictionary, classes or owner chains to get right; every CAD application reads it | Newer data cannot be written; `LWPOLYLINE` becomes `POLYLINE`; the round trip is lossless only for what the document models; unknown entities of R12 classes are written back, others are dropped with a warning until G2 |
| D8 | 2026-10-14 | Box selection is press-drag-release | It works the same with a mouse, a trackpad and in tests | AutoCAD users expect click-click windows as well |
| D9 | 2026-10-14 | Space submits the command line except at prompts that take text; it is handled in the input's change callback, not as a key binding | A binding would consume every space, including those typed into layer names and paths | A space typed at a text prompt cannot submit it; Enter does |
| D10 | 2026-10-14 | `View` has no rotation | Every spike feature works in an unrotated view, and the camera stays a centre and a scale | A rotated view, as the specification's `View.Rotation` allows, needs the transform threaded through picking and the adapter |
| D11 | 2026-10-14 | Every command-line submission clears the whole render cache | Layer colour edits are not journalled, so no change set reports them | Re-tessellating everything after each submission; harmless at spike sizes, wasteful on large drawings |
| D12 | 2026-10-14 | The application rasterizes icons with oksvg and rasterx | Both are pure Go, so the `js/wasm` build and the no-cgo rule hold; an icon becomes an alpha mask tinted by a theme colour | The review sheets are rendered by resvg, so the tool and the application differ slightly on edge pixels |
| D13 | 2026-10-14 | The icon tooling is Python run by `uv`, with Go code generation for the names, ported from Ubiq's Rust tooling; Lucide 1.57.0 is adopted under ISC | A script is quicker to change than a Rust tool, and resvg-py gives faithful sheets; the generated `names_gen.go` keeps Go compile-time names; adopted icons start from a coherent family | Contributors need `uv` and, for `icons-adopt`, npm registry access; the Lucide version is pinned in `tools/icons/icons.py` and its licence file ships in `assets/icons/` |
| D14 | 2026-10-14 | The agent manager is a nested stdlib-only module, `agentmanager`, that imports nothing from Cad-lite; the glue lives in `cadmcp` and `ui/agent*.go` | It is reusable and testable alone, like `internal/gpui`; the core stays free of process and network code | `go test ./...` from the root skips it, so it has its own check (`just check-agentmanager`); a `replace` directive in `go.mod` |
| D15 | 2026-10-14 | The agent reaches the drawing through an MCP server on loopback HTTP, protected by a per-session bearer token, closed with the session | Claude Code, Codex and opencode all consume MCP over HTTP; no extra process or socket protocol | Every tool call crosses HTTP and the UI-goroutine mailbox; the 16 ms drain timer bounds latency |
| D16 | 2026-10-14 | Permissions: the `cad` tools are auto-allowed, everything else asks the user, and no harness runs in a permissive mode | The drawing is undoable and is what the user asked the agent to edit; shell and file access are not | More prompts for agents that shell out; no allow-all switch |
| D17 | 2026-10-14 | `render_png` returns MCP image content (vision) rather than a separate CLI connected to the running instance | It works with every harness that accepts image results and needs no second program; the CLI-over-environment-variable alternative is in the backlog | Large image results consume agent context; a harness that drops images gets only the JSON mapping |
| D18 | 2026-10-14 | Agent conversations are stored per project in `<project>/.cad-lite/agent/` as JSONL (package `agentmanager/store`), several run at once as tabs on one shared `cad` server, and nothing agent related exists until the panel or the AI command is used | ACP replays no history on resume, so the host keeps its own transcript; the project directory is where the drawing lives; one server keeps one port and token for every session | A `.cad-lite/` directory appears next to the drawing after the first prompt; a changed project directory closes live sessions; the conversation is not stored inside the DXF |
| D19 | 2026-10-14 | macOS and Windows builds are pure Go (`CGO_ENABLED=0`, ebiten's purego) and cross-compile from any host; the Windows icon, manifest and version info come from a `.syso` that `go-winres` generates at build time and is never committed; Linux builds natively with cgo | One runner can build every target, and no C toolchain or SDK is needed for two of the three platforms | The macOS universal binary still needs `lipo` on a Mac; Linux needs the X11 and GL headers; the `.syso` files are deleted when a bundle script exits |
| D20 | 2026-10-14 | The application icon is an SVG source under `assets/appicon/`; the `.icns`, `.ico` and window PNGs are generated from it by `tools/icons/appicon.py` and committed; the ICNS file is written by Pillow rather than `iconutil` | `iconutil` exists only on macOS; committed outputs let a build on any host bundle the icon without running the generator | A changed SVG needs `just appicon` and a commit of the regenerated files |
| D21 | 2026-10-14 | Real-window behaviour is tested by driving the real binary under Xvfb with xdotool and screenshots, not by an input recorder inside the application | It exercises the true event path, ebiten and OpenGL, and adds no test-only code to the application | Needs Xvfb and Mesa on the machine; software GL makes frames slow, so key presses are held for 120 ms; HiDPI, the clipboard, IME and resizing are out of reach |
| D22 | 2026-10-14 | Settings are one TOML file in the OS user config folder, read and written with `github.com/BurntSushi/toml` (package `settings`, which knows nothing of the UI); unknown keys are kept and the file is written atomically | TOML is hand-editable and comments well; BurntSushi is pure Go, so the `js/wasm` build still works (there the settings live in memory); keeping unknown keys lets an older build run beside a newer one | One more module dependency; comments a user adds to the file are lost on the next save; the writer is hand-rolled to keep key order and comments |
| D23 | 2026-10-14 | The UI scale is a window-level zoom in `internal/gpui` (`Window.SetUIScale`), not a font-size setting or a per-token scale in `ui` | Text, icons, borders and hit boxes scale together with no view changing, and platforms need no change because the window divides pointer positions | The whole layout reflows at a smaller logical size; a drag that rescales the UI under the pointer is unstable, so the settings slider applies its value on release |
| D24 | 2026-10-14 | DWG is read by `fileio/dwg`, a pure-Go port of the reading logic of ACadSharp (MIT), not by the Open Design Alliance SDK or LibreDWG | ODA is a commercial C++ SDK that needs a cgo shim, and LibreDWG is C under GPLv3, which would license the whole application; both would also end the `js/wasm` and cgo-free builds. ACadSharp is MIT and reads every version from R14 to R2018, and the format's public specification covers the rest. The notice ships as `fileio/dwg/LICENSE-ACadSharp`. This settles backlog O1 and O4 | Cad-lite owns the format code: new object types are ported by hand, and the reader trails what ODA reads; LibreDWG and other GPL or LGPL source is never to be read for this package |
| D25 | 2026-10-14 | The DWG reader is read-only and imports only layers and the model space entities the document models; other entities are counted in a warning, not kept as `doc.Unknown` | Unknown entities are kept so a DXF can be written back, and a DWG cannot be written back; an unmodelled DWG entity has no group list to keep. Skipping and saying so is the honest result, and a drawing opened from DWG is saved as DXF | A DWG opened and saved loses TEXT, dimensions, blocks and hatches that the DXF route would keep as unknown objects; users who need them convert to DXF in a CAD application |
| D26 | 2026-10-14 | The spatial index is a uniform grid with a list for long entities and a handle-ordered list beside it, replacing D6's linear scan | Viewport culling ran a full scan and a full sort every frame; the grid answers a working view in time that grows with what it returns, and the ordered list answers zoom extents without a sort. Drafting drawings fill their extent evenly, which is a grid's best case, and a grid needs no rebalancing on edits | A drawing that is dense in one corner and sparse elsewhere packs that corner's cells until it grows enough for a new layout; every edit pays for keeping the ordered list sorted, which for an erasure of a few entities is a move of the list's tail |
| D27 | 2026-10-14 | Command-line submissions and mutating MCP calls refresh the render cache with `Builder.SyncLayers`, replacing D11's clear on every submission | Entity edits reach the cache through change sets; only unjournalled layer edits needed the full clear, and `SyncLayers` detects those by comparing the layer table with the copy the cache was built against | Each submission compares the layer table (one pass over a short slice); a layer field that affects drawing but is not in the compared set would leave stale items, so a new one must be added to `layerLook` |
| D28 | 2026-10-14 | Files the OS hands over reach one function, `Workspace.OpenPaths`, which runs OPEN; on macOS the open-documents event is taken by an `NSAppleEventManager` handler installed through `purego/objc`, not by adding `application:openFiles:` to GLFW's application delegate | One path for drops, Finder and Dock opens and file arguments keeps the unsaved-changes question and the reports in one place, and N1 changes only that function to open tabs. The Apple event handler is independent of ebiten's delegate class, which is registered inside `ebiten.RunGame` too late to patch before a launch-by-document event | The handler must be reinstalled from a will-finish-launching observer because AppKit installs its own while launching; a launch event that arrives before that would be lost, and it cannot be tested off a Mac |
| D29 | 2026-10-14 | Agent conversations belong to a drawing through an open-tab set per drawing file name inside the project store of D18 (`open-<hash>.json` next to `open.json`, plus a `drawing` line in each record), not a sidecar file next to the drawing and not a store per drawing; Save As moves the set within a project and copies the records into another project's store | One store per project keeps the history of every drawing in one place and the agent's working directory unchanged; nothing new appears next to the drawing; an untitled drawing keeps `open.json`, and a store written before this adopts its open tabs into the first drawing opened | A drawing renamed or moved outside Cad-lite loses its tabs (the records stay in History); conversations copied to another project resume only where the agent keeps sessions independent of the directory (Claude keys them by directory) |
| D30 | 2026-10-14 | A model change applies to the live session through the harness's own switch (Claude `set_model` control request, ACP `session/set_config_option` or `session/set_model`, Codex `turn/start` `model`), exposed as the optional `agentmanager.ModelSetter`; without one, and to return to the default, the panel ends the session and the next prompt resumes it on the new `Config.Model` | No restart, so no lost process state, where the protocol allows; the optional interface keeps `Session` frozen | Two paths to test; a restart costs an agent start and relies on resume |
| D31 | 2026-10-14 | Cad-lite installs OpenCode itself, only on a click and after a question, through a mise release binary downloaded into its own tools folder, verified against the release's SHA256 list and run with every mise directory, its config and the working directory inside that folder; the result is stored as `agent.binaries.opencode` | A user without any agent gets one without a terminal, a package manager or a change to their shell or global mise; mise picks a working backend (npm or release binaries) per platform; no `curl \| sh` | Up to about 1 GB of disk and a download from github.com; the checksum list comes from the same release, so it guards against corruption, not a compromised release; the npm backend needs node on the PATH; opencode is found by `mise which`, so a mise change in that command breaks the step |
| D32 | 2026-10-14 | Several open drawings are document tabs: `ui.Workspace` embeds the active `docTab` (session, view, display cache, canvas state, file, agent state) and keeps the shell shared; the file commands reach the tabs through a `cmdsys.DocumentHost` installed per session; each document tab's agent conversations have their own `cad` MCP server whose tools act on that tab's session, so an agent session stays bound to the tab it was started in while the panel shows the active tab's conversations | Embedding the active tab keeps every `ws.session`/`ws.view` read in the shell unchanged; the host interface keeps `cmdsys` free of UI and leaves a host with one drawing as it was; binding a session to its drawing means an agent working in the background never edits the drawing the user switched to, and per-drawing conversations (D29) belong to one drawing anyway | One MCP server (one port) per document tab with a live agent; code that must act on a background tab names the tab explicitly; QUIT asks about every dirty tab through a chain of QUIT commands rather than one dialog |
