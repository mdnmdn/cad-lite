# Code review: Cad-lite @ c48c7ec (committed state)

Reviewed in a throwaway worktree (removed afterwards). Throwaway tests lived only there.
CONFIRMED = reproduced with a failing input or throwaway test. PLAUSIBLE = read from code, not reproduced.

## Summary

The codebase is in good shape: clean `go vet` in both modules, `go test -race` green in the nested module and in the root
(see tool notes), layering rules hold (verified with `go list -deps`), the MCP server is loopback-only with host/origin
checks, constant-time bearer compare, body cap and `ReadHeaderTimeout`; tokens never go in argv (Claude: 0600 temp file,
Codex: env var, ACP: redacted in frame log). A 40k-case random-script fuzz over every command found no panics.

The real risks are on the agent surface and in data handling, not in memory safety:

1. The auto-approve policy (`AllowMCP`) trusts a **title prefix** and is spoofable by non-MCP tools (F1).
2. Every `cad` tool, including `run_script`, is auto-approved, and `run_script` can run NEW / OPEN / SAVE: it can discard
   the user's unsaved drawing and undo history, and overwrite any `*.dxf` on disk, with no prompt (F2).
3. NaN/Inf are accepted by the command-line number parser and the DXF reader, then poison the view and the written DXF (F3).
4. File save is non-atomic and a truncated DXF opens "successfully" as an empty drawing (F4, F5).

## Security of the agent/MCP surface

Good:
- Listener: `tcp4 127.0.0.1:0`, random 32-byte token (crypto/rand), `subtle.ConstantTimeCompare`, Host must equal `127.0.0.1:port` or `localhost:port` (DNS-rebinding safe), `Origin` must be loopback when present, POST only, 4 MiB `MaxBytesReader`, auth checked before the body is read, `ReadHeaderTimeout` 10 s, one server per agent session closed on stop.
- Secrets: Claude config in a 0600 `CreateTemp` file removed on exit (argv would leak via `ps`); Codex token via env var name only in `-c`; ACP frame logs redact the token; Claude strips its own `CLAUDECODE*` env.
- Agents run with prompts on by default: Claude `--permission-prompt-tool stdio` and `--strict-mcp-config`; Codex `read-only` sandbox plus `on-request`.
- Tool arguments are decoded strictly (unknown fields rejected, required keys checked, trailing data rejected, finite checks, handle validation).

Weak (see findings): F1 (spoofable auto-approve), F2 (auto-approved `run_script` reaches destructive file commands; no path policy), F3 (non-finite numbers via `run_script` bypass the `finite()` checks), F6 (orphan agent on quit), F10/F11 (resource bounds), the MCP config temp file lives in the shared `os.TempDir()` for the session lifetime and is not removed if the app is SIGKILLed (token is per-run random so the leaked file is inert, but the path/name is predictable-prefix; a private `0700` dir from `MkdirTemp` would be tidier).
Other notes: the agent's `Cwd` defaults to the process cwd (whole project tree readable if the user approves reads). `Config.Args`/`Env` are passed through unfiltered; fine while only the CLI sets them. The Codex MCP entry sets `default_tools_approval_mode="approve"`, so Codex never asks for cad tools by design; combine with F2.
govulncheck could not run (proxy 403 on vuln.go.dev); dependency review by hand: root uses go-text/typesetting, ebiten; the nested module has no third-party deps.

## Test gaps

- No negative tests for `AllowMCP` against shell-like titles (F1).
- No test that `run_script` cannot NEW/OPEN/SAVE (F2), nor for NaN/Inf in `ParseInput` and the DXF reader (F3).
- No fault-injection test for `Registry.Save` (short write / failing writer) (F4); no truncated/garbage DXF open test (F5).
- No test of panic in a command inside `withTx`/Session (F7); the dispatcher recovers but the Session state after recovery is untested.
- `strokeBuf` resize with equal area (F8); rasteriser tests cover content not buffer reuse.
- `ui` agent: quit during `agentStarting` leaves a session open (F6) is untested; `fakeagent` could model a slow Open.
- `jsonrpc`: write-failure goroutine leak and over-long line behaviour (F10).
- `mcp`: Host header, Origin, wrong method and batch paths exist; add oversized batch, cancelled ctx while waiting on `callMu`.
- `cmdsys/commands` fuzz target: promote the throwaway random-script test (no panics at 40k seeds) to a `go test -fuzz` target with NaN/1e308 tokens in the pool.

## Quick wins vs deeper refactors

Quick (each under an hour): F8, F9, F10 (write-loop break + line cap), F3 (shared finite parse helper), F4 (atomic save), F5 (EOF/ENDSEC check), F1 (tighten matcher + tests), F14, F15.
Medium: F2 (policy: deny or confirm file/replace commands for agent callers, dirty flag + confirm in UI), F6 (join opener goroutine), F7 (panic-safe Session/txn), F11.
Deeper: F12 (R-tree + layer index + selective invalidation + O(1) erase), F13 (off-UI-goroutine snapshot).
